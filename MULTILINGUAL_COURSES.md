Each new course covers greetings, people, numbers, food, places and actions, ten
vocabulary entries per lesson. Every entry has an example, its English
translation and tags. Each lesson has two multiple-choice exercises, one
matching exercise, two gap exercises, translation, listening and speaking.
Examples and translations are authored starter content; native-speaker editorial
review is still recommended before publishing a curriculum.

## Use and behavior

New accounts choose from the six courses during onboarding. Existing accounts
open **Profile → Settings → Learning language**, tap a course, then go back to
Learn. Selection saves immediately, preserves the daily goal, and displays a
retryable message if preferences cannot be saved. The picker is scrollable and
uses the existing light/dark theme, semantics and touch targets.

Riverpod providers are reactive state/dependency containers: changing the saved
course makes the existing Learn, Review, audio and Chat providers reload it.
Lesson and word IDs have distinct language prefixes, so completing Spanish
cannot unlock a French lesson or schedule a French word. XP, streaks and daily
activity stay account-wide. Switching back restores the original course's path
and due cards. The existing sync protocol already stores these string IDs;
there is no new Supabase table or SQL migration.

Audio uses the existing recording/cache/TTS fallback; these new courses contain
no recorded files. Install a matching device voice for pronunciation, and a
supported recognition language for speaking. Existing missing-voice and
microphone-denial states still apply. French, German, Italian and Portuguese now
have accent helper buttons, alongside Spanish. Japanese uses the device keyboard.

The local Drift schema moves from version 5 to 6, adding `course_id` to chat
entries. Drift is the app's typed SQLite layer. Old conversations default to
`ja_basics_en`; new replies and restored scenarios are filtered by course. The
last-20-message limit remains global per account, so older messages can still be
trimmed as you chat in other courses. No conversation is uploaded by this migration.

## Backend update required for multilingual Chat

The client now sends `targetLocale` with each chat request. The Edge Function
accepts only the six known locales and derives the prompt language server-side;
clients cannot inject arbitrary system-prompt text through this field. Portuguese
uses a Brazilian Portuguese tutor. Safety redirects also use the chosen language.
Authentication, quotas, request limits and server-only Groq secrets are preserved.

Redeploy the updated function to your linked Supabase project:

```powershell
supabase functions deploy chat
```

An older deployed function ignores `targetLocale` and continues using its global
`TUTOR_LANGUAGE`, so update it before testing multilingual AI conversations.
Requests from old clients without `targetLocale` retain the server's language
setting (Japanese by default). This change was verified locally with a fake
provider, not by deploying or spending live Groq quota.

## Content maintenance

The five UTF-8 files under `tool/course_sources/` are the editable sources. Each
line contains `text|translation|example|exampleTranslation`; keep the six ordered
groups of ten. Edit these sources, regenerate assets and review the JSON diff:

```powershell
python tool/generate_courses.py
python tool/generate_courses.py --check
```

The generator validates row counts and examples, generates deterministic options,
and checks duplicate IDs. Word IDs derive from the English translation; after
release, treat translations used in IDs as stable and explicitly migrate IDs if
you change them. Existing source lines should not be reordered across themes.
Japanese is maintained separately and is never regenerated by this tool.

## Run and verify

From `C:\Langunge_flutter\myapp`, use your existing ignored local configuration:

```powershell
flutter pub get
flutter run -d chrome --dart-define-from-file=config.local.json
```

For Android, launch an emulator with `flutter emulators --launch <emulator-id>`,
then `flutter run -d <device-id> --dart-define-from-file=config.local.json`.
Use `flutter devices` to find the actual ID. Restart the app after updating to
ensure Flutter packages the new assets and Drift opens/migrates the database.

```powershell
python tool/generate_courses.py --check
flutter analyze
flutter test
node --experimental-strip-types --test supabase/tests/chat_handler.test.ts
deno task --config supabase/functions/chat/deno.json check
flutter build web --release --dart-define-from-file=config.local.json
```

global ID uniqueness, actual asset loading, pronunciation locales and accents,
onboarding, Settings at 360 dp with enlarged text, failed-save retry, a full
Spanish lesson with 50 XP and ten enrolled words, separate progress/reviews/chat,
legacy database migration, and locale propagation through the API/server.

Manual checks: change to each language, play its listening/speaker audio, try
speaking with an installed locale, complete a lesson, inspect Review, switch
